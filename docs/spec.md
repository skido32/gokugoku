# ゴクゴク 仕様書

> 版: 0.1(ドラフト) / 対象: MVP
> 設計の詳細は [design.md](design.md)、設計判断は [adr/](adr) を参照。

## 1. 概要

### 1.1 目的
**双子の授乳のタイミングを、夫婦でワンタップで記録・共有する**アプリ。ストアの表示は「ゴクゴク - 双子の授乳記録」。
「最後にいつ、どちらの子に飲ませたか」を、開いてすぐ分かる状態にする。

### 1.2 背景・課題
- 既存の育児アプリは多機能で、授乳中の片手操作には重く、続かなかった(作り手自身が双子の親としての実体験)。
- 双子では、1人ずつ画面を切り替えて入力するのが手間になる。2人同時に飲ませることも多い。
- 夫婦で交代して世話をすると、「最後にあげたのはいつか」が分からなくなる。
- シンプルな記録アプリ(ミルクのーと)には、夫婦の共有と、複数人の記録がない([competitors.md](competitors.md))。

### 1.3 方針
- **引き算の設計**: 機能を絞り、記録は最短の操作で完了させる。
- **双子に特化した、シンプルな授乳記録アプリ**として作る。最も近い競合は、ミルクのーと。これに、**夫婦の共有**と、**1画面で2人分の記録**を加える。
- クライアントは、React Native(Expo)のアプリ([ADR 0002](adr/0002-react-native.md))。
- 認証は、登録なしの匿名アカウント([ADR 0003](adr/0003-anonymous-account.md))。メールアドレスも持たない。
- 画面は、2人を前提に最適化する。ただし、子ども1〜4人で使えるようにしておく(1人の家庭、三つ子にも対応できる)。
- 記録と目安の表示にとどめ、医療的な助言や診断は行わない。

### 1.4 用語
| 用語 | 意味 |
|---|---|
| 家族 | データ共有の単位。子どもと利用者(夫婦など)が属する。 |
| 授乳記録 | 「いつ・どの子に・どう飲ませたか」の1件。 |
| 操作 | 1回のタップ。「全員」の場合は、子どもの数だけの授乳記録を束ねる。 |
| 種類 | ミルク / 母乳 / **混合**。混合は、1回の授乳で、母乳のあとにミルクを足すこと。 |
| いつもの種類 | 子どもごとに設定する種類。授乳ボタンを押すと、この種類で記録する。 |

## 2. 利用者

| 利用者 | 説明 |
|---|---|
| 主たる利用者 | 双子のいる家庭の親(夫婦)。深夜・片手・短時間で使う。 |
| 家族メンバー | 祖父母、シッターなど。MVP では夫婦以外の利用は想定しないが、制限もしない。 |

利用環境: スマートフォンのアプリ(iOS、Android)。まず TestFlight と内部テストで、家族に配る。

## 3. スコープ

### 3.1 MVP に含む
1. 登録の操作なしで使い始める(初回起動で、利用者を自動で作る)。機種変更用の引き継ぎコード
2. 家族の作成と、パートナーの招待
3. 子どもの登録(2人。データ上は N 人)
4. 授乳の記録(子どもごと / 全員、ワンタップ)
5. 前回の授乳からの経過時間の表示
6. 直近の履歴の表示、取り消し、内容の修正
7. パートナーの記録の反映(数秒以内)
8. アカウント・家族データの削除

### 3.2 MVP に含まない(後回し)
- リマインド・プッシュ通知
- 睡眠、排泄、体温など授乳以外の記録
- グラフ、成長曲線、統計
- 写真、コメント、SNS・コミュニティ
- 複数家族への所属、役割ごとの細かい権限
- 多言語対応(日本語のみ)
- 永続的なオフラインキュー(MVP では失敗時の再送までとする)
- 記録のエクスポート(CSV)。保持期間が90日と短いため、MVP では不要とする
- 90日を超える長期の履歴

## 4. ユースケース

| ID | 利用者の目的 | 操作 |
|---|---|---|
| UC-1 | 授乳したので記録する | ホームで、子どものボタン、または「全員」(子どもが2人以上のとき)をタップする。 |
| UC-2 | 間違えて押したので取り消す | 直近の履歴から「取り消し」をタップする。 |
| UC-3 | 前回の授乳を確認する | ホームを開く。子どもごとに経過時間が見える。 |
| UC-4 | 母乳かミルクか、量を残す | 記録した直後の表示、または履歴から、種類や量を追記・変更する。 |
| UC-5 | 後からまとめて記録する | 履歴の追加から、時刻を指定して記録する。 |
| UC-6 | パートナーを招待する | 設定で招待コード(リンク付き)を発行して、LINE などで送る。 |
| UC-7 | 家族に参加する | アプリを入れ、初回ガイドで「招待コードで参加」を選び、コードを入力する(リンクを開いてもよい)。 |
| UC-8 | 機種変更する | 古い端末の設定で引き継ぎコードを発行し、新しい端末で入力する。 |

## 5. 機能要件

### 5.1 認証・アカウント
| ID | 要件 |
|---|---|
| F-AUTH-1 | 初回の起動で、利用者を自動で作る。メール、パスワード、電話番号の入力は求めない([ADR 0003](adr/0003-anonymous-account.md))。 |
| F-AUTH-2 | ログイン状態は端末に保存し、時間では切れない。設定から、他の端末のログイン状態を失効できる。 |
| F-AUTH-3 | 設定で**引き継ぎコード**を発行できる。24時間有効で、1回だけ使える。新しい端末で入力すると、同じ利用者として使える。使うと、元の端末のログイン状態は失効する。 |
| F-AUTH-4 | 端末を失っても、家族に他の利用者がいれば、招待し直して参加できる(記録は家族に残る)。1人だけの家族で引き継ぎコードもない場合、データは戻せない。初回ガイドでパートナーの招待を勧め、設定でこのことを案内する。 |
| F-AUTH-5 | 招待コードと引き継ぎコードは、推測されにくい長さにし、入力の試行回数を制限する。 |

### 5.2 家族・招待
| ID | 要件 |
|---|---|
| F-FAM-1 | 初回ガイドで**自分の呼び名**を入力し、「家族を作る」か「招待コードで参加する」を選ぶ。呼び名は履歴の記録者として表示される。 |
| F-FAM-2 | 家族の作成者は「オーナー」、他の参加者は「メンバー」とする。 |
| F-FAM-3 | 招待コード(リンクでも開ける)は7日間有効で、1回だけ使える。再発行すると古いコードは無効になる。 |
| F-FAM-4 | 家族の利用者は最大6人とする。 |
| F-FAM-5 | 利用者は1つの家族にのみ所属できる(MVP)。 |
| F-FAM-6 | オーナーはメンバーを家族から外せる。メンバーは自分で退出できる。 |

### 5.3 子ども
| ID | 要件 |
|---|---|
| F-CHILD-1 | 家族に子どもを登録できる。名前(ニックネーム可)は必須、生年月日は任意。 |
| F-CHILD-2 | 子どもごとに識別色が自動で割り当てられる。後から変更できる。 |
| F-CHILD-3 | 子どもの人数は1〜4人。ホームの表示は人数に応じて切り替える(1人: 大きなボタン1つ、2人: 左右に並べる、3〜4人: 縦に並べる)。 |
| F-CHILD-4 | 子どもの名前・色・並び順を変更できる。削除すると、その子の記録も削除される(確認あり)。 |
| F-CHILD-5 | 子どもごとに「いつもの種類」(ミルク / 母乳 / 混合)を設定できる。既定はミルク。子どもによって種類が違う家庭に対応する。 |

### 5.4 授乳記録
| ID | 要件 |
|---|---|
| F-FEED-1 | ホームの、子どもごとのボタン、または「全員」ボタンを1回タップすると、**確認なしで**即記録する。 |
| F-FEED-2 | 記録の時刻はタップした時刻(サーバーが受信した時刻ではなく、端末の時刻を基準にし、サーバー側で妥当性を検証する)。 |
| F-FEED-3 | 種類は、ミルク / 母乳 / 混合 の3つ。ボタンで記録すると、その子の「いつもの種類」(F-CHILD-5)で記録する。例外の回は、記録した直後に変えられる(F-FEED-11)。 |
| F-FEED-4 | 量(ml)は任意で、記録後に追記できる。量を持つのは、ミルクと混合だけ(混合は、足したミルクの量)。母乳の量は記録しない。 |
| F-FEED-5 | 記録者(ログイン中の利用者)が自動で残る。 |
| F-FEED-6 | 「全員」は子どもの数だけ記録を作り、取り消しはまとめて行う。「全員」ボタンは、子どもが2人以上のときだけ表示する。ボタンの表示は、2人なら「ふたりに授乳」、3〜4人なら「みんなに授乳」。 |
| F-FEED-7 | 通信の再送や二重タップで、同じ操作が二重に記録されない。押したボタンは、3秒間「記録しました」と表示して押せなくする。 |
| F-FEED-8 | 履歴の記録は、種類・量・時刻を後から修正できる。 |
| F-FEED-9 | 時刻を指定した後追いの記録ができる(未来の時刻は不可)。 |
| F-FEED-10 | 同じ子に、他の人が直近5分以内に記録済みの場合、**記録は受け付けた上で**「〇〇さんが2分前に記録済みです」と知らせる。 |
| F-FEED-11 | 記録した直後に「記録しました」を5秒表示する。その間に、種類の変更(1タップ)、量の入力、取り消しができる。複数の子をまとめて記録したときは、子ごとの種類を表示し、[直す] から全員分を1画面で直せる。5秒を過ぎた後の修正・削除は、履歴から行う。 |
| F-FEED-12 | 端末ごとの設定「押したら量の入力を開く」をオンにすると、記録した直後に量・種類の入力が自動で開く。既定はオフ。 |

### 5.5 表示
| ID | 要件 |
|---|---|
| F-VIEW-1 | ホームには、子どもごとに前回の授乳からの経過時間を大きく表示する。 |
| F-VIEW-2 | 経過時間は1分ごとに更新する。端末の時刻のずれを、サーバー時刻で補正する。 |
| F-VIEW-3 | 直近の履歴を新しい順に表示する(既定で24時間分、続きは追加読み込み)。表示できるのは、保持期間(90日)内の記録に限る。 |
| F-VIEW-4 | 履歴には、時刻・子ども・種類・量・記録者を表示する。 |
| F-VIEW-5 | パートナーの記録は、画面を開いている間、5秒以内を目安に反映される。 |
| F-VIEW-6 | 記録がまだない子どもには「記録なし」と表示する。 |

### 5.6 データ管理
| ID | 要件 |
|---|---|
| F-DATA-1 | 利用者は自分のアカウントを削除できる。 |
| F-DATA-2 | 家族の最後の利用者が削除すると、家族と子ども、記録をすべて削除する。 |
| F-DATA-3 | 授乳記録は**90日間だけ保持**し、それより古い記録は自動で削除する。 |
| F-DATA-4 | 保持期間(90日)より前の時刻を指定した記録は、受け付けない。 |

## 6. 画面

| 画面 | 内容 |
|---|---|
| 初回ガイド | 自分の呼び名 →「家族を作る」(家族名、子ども2人の登録、パートナー招待)か「招待コードで参加」(コード入力)。ログイン画面はない。 |
| **ホーム** | 子どもごとの経過時間、直近の履歴、子どもごとの授乳ボタン、「全員」ボタン(2人以上のとき)。記録した直後の表示(種類の変更・量・取り消し)。 |
| 履歴 | 日付ごとの一覧。修正・削除・後追い記録。 |
| 設定 | 子ども(名前・色・並び順・いつもの種類)、家族メンバー、招待、押したら量の入力を開く(端末ごと)、引き継ぎコード、他の端末のログアウト、アカウント削除。 |
| 招待受諾 | 招待リンクを開いたときの参加確認(アプリが入っていなければ、ストアへ案内する)。 |

### ホームのレイアウト
子どもが2人の場合の例(1人のときは、経過時間とボタンを1つだけ大きく表示し、3〜4人のときは縦に並べる)。
```
┌──────────────────────────────┐
│  (A) A くん          (B) B くん   │
│  前回から 2時間10分   前回から 1時間05分 │
│  21:40 ミルク 120ml   22:45 混合 40ml  │
│                              │
│  直近の記録                   │
│  22:45  B     混合 40ml   ママ   │
│  21:40  A・B  ミルク 120ml パパ   │
│                              │
│  [  A に授乳  ]  [  B に授乳  ] │
│  [        ふたりに授乳        ]  │
│  ホーム      履歴      設定     │
└──────────────────────────────┘
```
授乳ボタンは、親指の届く画面の下に置く。画面ごとの詳細と、決まった見た目は [ui-brief.md](ui-brief.md) と [design.md](design.md) 5.4 を参照。

画面の方針:
- ボタンは親指で押しやすい下寄りに置き、十分な大きさにする(最小 56px)。
- 子どもは**色と位置(左右固定)**で区別し、色だけに頼らない(名前も常に併記する)。
- 昼はピンクとベージュ、夜は眩しくないココア色の配色にする(ダークモード)。
- 記録の完了は、確認ダイアログではなく、短い表示と振動で伝える。

## 7. 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 記録のタップから画面への反映まで、通常の回線で1秒以内。ホームの初回表示は3秒以内。 |
| 可用性 | 個人開発の無料〜低額構成を前提とし、厳密な SLA は設けない。ただし、データを失わない。 |
| 信頼性 | 通信が不安定でも、記録の二重登録・欠落を起こさない(冪等な API とクライアントの再送)。 |
| セキュリティ | 通信は TLS。他の家族のデータは見えない。トークンはハッシュ化して保存する。 |
| プライバシー | 子どもの情報は最小限(名前はニックネーム可)。授乳記録は90日で削除する。広告・第三者の解析ツールを使わない。 |
| 互換性 | iOS と Android の直近2メジャーバージョン。 |
| アクセシビリティ | 文字拡大に対応し、色だけに依存しない。 |
| 保守性 | 自動テストと CI を備える。設計判断を ADR に残す。 |

## 8. 制約・前提
- 運用は個人。サポート窓口は設けない。
- 本サービスは**記録のための道具**であり、授乳量や間隔の適切さを判断・助言しない。利用規約と画面に明記する。

## 9. 受け入れ条件(主要なもの)

| 対象 | 条件 |
|---|---|
| UC-1 | ホームで「A」をタップすると、確認なしで記録され、A の経過時間が0分になる。 |
| UC-1 / F-FEED-6 | 子どもが2人のとき「全員」をタップすると2件記録され、取り消しで2件とも消える。子どもが1人のとき、「全員」ボタンは表示されない。 |
| F-FEED-7 | 同じリクエストを2回送っても、記録は1件のまま。 |
| F-VIEW-5 | パートナーが記録すると、5秒以内に自分の画面にも反映される。 |
| F-FEED-10 | 同じ子に5分以内に別の人が記録しても、拒否されず、通知付きで記録される。 |
| F-FEED-3 / F-CHILD-5 | A のいつもの種類がミルク、B が混合のとき「ふたりに授乳」を押すと、A はミルク、B は混合で記録される。 |
| F-FEED-11 | 記録した直後の表示で「母乳」を押すと、その記録の種類が母乳になり、量は空になる。 |
| 認可 | 別の家族の記録を、取得・変更・削除しようとすると 404 になる。 |
| F-AUTH-1 | 初回起動で、入力なしにホームまたは初回ガイドが開く。 |
| F-AUTH-3 | 使用済み・期限切れ・誤りの引き継ぎコードでは、引き継げない。引き継ぐと、元の端末は 401 になる。 |
| F-AUTH-5 | 招待コード・引き継ぎコードの入力を誤り続けると、回数制限(429)になる。 |

## 10. 未決事項
| # | 論点 | 暫定 |
|---|---|---|
| 1 | メールの登録(任意の引き継ぎ手段) | MVP では持たない。端末の紛失でデータを失う家族が出たら検討(ADR 0003) |
| 2 | 授乳の「開始・終了」(所要時間)を記録するか | MVP は時刻1点のみ |
| 3 | 母乳の左右(どちらの乳房か)、母乳の時間の記録 | MVP では扱わない。記録の項目が増え、「押すだけ」の手軽さが落ちるため。使ってみて必要なら追加する |
| 4 | サービス名 | **ゴクゴク**(ストアの表示は「ゴクゴク - 双子の授乳記録」)に決定。商標とドメインは公開前に確認する。リポジトリ名・ディレクトリ名・DB 名は `gokugoku` に変更済み |
| 5 | 公開範囲(身内のみか、一般公開か) | まず身内のみ。公開時に規約を整備 |
| 6 | 保持期間(90日)は、後から変えられるようにするか | 固定。使ってみて足りなければ見直す |
