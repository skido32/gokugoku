# 0001: 構成の方針

> 状態: 採用 / 日付: 2026-11-16(2026-11-22 にクライアントの部分を更新)

## 決定
- モノレポにする。`api/`(Rails の API)、`app/`(React Native / Expo)、`web/`(Next.js の静的ページ)を分け、API は OpenAPI で契約する
- クライアントは React Native(Expo)のアプリ(詳細は [0002](0002-react-native.md)。当初は PWA 先行の方針だったが、変更した)
- リアルタイム反映は、最初はポーリング。必要になれば Action Cable へ
- 授乳記録は `client_request_id` で冪等にし、「全員」の記録は `operation_id` で束ねる
- 取り消しは論理削除(`deleted_at`)

## 理由
- API を独立させておけば、クライアントを増やしても(Web 版など)バックエンドを再利用できる
- 通信が不安定でも二重記録されない設計を、最初から入れておく
- ポーリングは、無料枠の構成(Neon のスリープ)と相性がよく、実装も単純

## 見直す条件
- 5秒のポーリングでは、夫婦の記録の反映が遅いと感じる場合 → Action Cable(または SSE)を検討
- ポーリングで、Neon の無料枠の計算時間が足りなくなる場合
