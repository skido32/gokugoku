# 0002: クライアントは React Native(Expo)のアプリで提供する

> 状態: 採用 / 日付: 2026-11-22
> 経緯: 2026-11-16 に「PWA で提供し、アプリ化は見送る」と決めたが、方針を変更した。

## 決定
- クライアントは、**React Native(Expo)のネイティブアプリ**とする。
- Rails の API(`/v1`、OpenAPI)は、そのまま使う。認証は **Bearer** とし、トークンは端末の Keychain / Keystore に保存する。
- Next.js(`web/`)は、アプリ本体ではない。プライバシーポリシー、説明ページ、招待リンクの受け口(ユニバーサルリンク)に絞る。

## 方針変更の理由
- 製品の位置づけを、「双子に特化した、シンプルな授乳記録アプリ」に決めた。最も近い競合は、**ミルクのーと**(ミルクの時間に特化。ウィジェットから1タップ)である。これと並ぶには、ウィジェット、通知、起動の速さが要る。PWA では、手数で負ける。
- 夜中に片手で使うため、「ホーム画面から開いて、1タップ」より、ウィジェットや通知のほうが、使われ続けやすい。毎日使われ続けることを、何より優先する。

## 差別化(ミルクのーととの比較)
- **夫婦で共有できること。** ミルクのーとは、夫婦の共有と複数人の記録に非対応(実際に触って確認済み)。
- **1画面で、2人分の授乳を記録できること。** 「全員」ボタンと、2人を並べたホームで、画面の切り替えを要らなくする。
- 対象は、双子の家庭。ただし、データモデルは、子ども1〜4人を扱える形のまま残す(画面は、2人を前提に最適化する)。

## 受け入れるコスト
| 項目 | 内容 |
|---|---|
| 費用 | Apple Developer 年約1.5万円、Google Play 初回$25。公開を続ける間のみ |
| 工数 | PWA より、約7〜10日増える見込み(署名、審査、実機確認、ユニバーサルリンク) |
| 配布 | まず TestFlight と Android の内部テストで、家族に配る。ストア公開は、使用感を見てから決める |
| ウィジェット | Expo では、ネイティブのコード(iOS は Swift の WidgetKit)が要る。MVP の後に、追加する |

## 期限のゲート
- 実装の開始から4週間後までに、TestFlight で、家族が使える状態にする。間に合わない場合は、同じ API で、簡易な Web 画面を先に出す。
- 授乳の記録が必要な時期は限られる。使い始めの遅れが、そのまま、使える期間の短縮になる。

## 見直す条件
- Apple Developer の登録や、審査が進まず、期限に間に合わない場合。
- 家族で使ってみて、ウィジェットや通知が、必要ないと分かった場合(PWA に戻す余地がある)。

## 検討した別案
PWA(Next.js)。費用が0円で、リンクだけで配れ、工数が小さい。一方で、ウィジェットと安定した通知が使えず、夜間の使い勝手で、ミルクのーとに劣る。位置づけを変えたため、見送った。
